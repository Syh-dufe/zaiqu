# Continuous Sundial and scheduled LLM refresh on Poisson demand

User clarified that predictions should remain active and synchronized with routine demand reports, without synthetic shocks or waiting for emergency notice. Compare the full updated policy against frozen Poisson-trained HAPPO on identical paths.

Each newly delivered 3-period report triggers a local Sundial update using only delivered demand history. The currently accepted rule pool is re-evaluated against the updated forecast and current inventory state at each report. No rules are created before the first fixed refresh point. LLM generates/revises candidates at decision periods 19,64,109,154 only (four events; within the original 16-HTTP per-episode ceiling). These points are set before path/cost evaluation. Each event retains original candidate generation, search feedback, revision guard, independent candidate-pool review, 5-period action application, six-rule DSL, ±6 correction bound, 20-period prediction horizon, and episode-local memory. No external notification or hidden future event information is passed. LLM prompt describes routine scheduled updates. Frozen HAPPO and Sundial weights/adapters remain fixed.

Development pilot: two pre-existing Poisson10 baseline-development paths, all HAPPO seeds11..15, leads2/4. These data were already used in Base-stock target development, so this is explicitly a development pilot and cannot be called independent confirmation. 40 episodes,24000 node-periods; paired HAPPO re-evaluated on identical paths.
