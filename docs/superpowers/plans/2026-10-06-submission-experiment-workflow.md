# 投稿补充实验流程计划

> **For agentic workers:** 执行时使用 executing-plans，逐阶段登记、审核和报告。以下复选框表示尚未执行的任务。本文件是流程设计，不是已完成实验，也不是各批正式运行登记。

**Goal:** 在已有基线结果上，验证冻结HAPPO与实时LLM机制的组件贡献、信息贡献、适用范围和计算代价。

**Architecture:** 复用相同条件下已有完整记录，只补新增方法；追加分析与前瞻确认分开。原主方法、库存模型和五个正常需求训练HAPPO固定，变体写入独立目录。机制冻结后生成新确认输入，成绩不反馈提示优化。

**Tech Stack:** 项目已有Python/PyTorch CPU运行环境、DeepSeek API、JSON/CSV原始记录、逐期审核和模型/路径交叉bootstrap。

## 一、已有成果与本计划范围

已完成五个HAPPO和五个IPPO正常需求训练、四类需求冲击确认、三方法共同确认及Base-stock事后追加比较。当前共同路径冲击成本：HAPPO20.742775，IPPO22.497533，原实时LLM＋HAPPO20.242033，Base-stock z=2为20.536708、z=8为32.895792。

LLM与IPPO、z=2的成本区间跨零，不能写成全面显著胜出。报告触发升级与残差预测替换未通过原开发门槛，保留负面结果，不恢复这些任务。已有成果主要支撑整套机制的效果，尚未隔离各组件和额外信息的贡献。

本计划不重新训练HAPPO，不微调DeepSeek，不增加随机候选比较，不恢复已取消定时任务。README新增内容只展示成本；原始全部指标、原策略内部接纳条件和不利结果保留。用户要求先制定计划，本次不运行仿真、不调用API。

### 路线选择

| 路线 | 优点 | 局限 | 本计划安排 |
|---|---|---|---|
| 只复用历史路径做新增方法 | 节省原方法/API重复运行 | 属于事后追加；新旧API输出不构成固定回复反事实 | 先做，作为开发和描述 |
| 所有方法在新路径共同确认 | 可事前登记检验，当前API部署条件一致 | 原LLM需要重新现场调用 | 在机制与实现冻结后做 |
| 继续增加算法、环境或调参 | 可拓展研究范围 | 成本高，仍不能替代组件贡献证据 | 暂不优先；MAPPO、交通损毁、资源模型另列扩展 |

## 二、通用规则

- 五个模型种子11—15全保留，使用原正常验证选定的best，不根据灾情选checkpoint或种子。
- 原库存初始状态、提前期4、动作0—20、200期、三级节点、需求截断及四类冲击定义保持。报告k=3、通知延迟2为主设置。
- 原主方法SYSTEM、Client、大小写解析与修复、候选0替换、3条搜索与3条复核路径、原接纳门槛、5期筛选、最多4次生成和回合记忆清空固定。
- 原 `online_once` 实现仍在首次事件做预测反馈修订，后续继续筛选；不能将其称为“无反馈”。
- 正常场景不调用API，LLM方法动作应等于HAPPO；通知前也必须一致。
- 旧路径、失败登记曾生成的路径和历史确认路径均算已暴露资料。新路径只在所有方法与分析协议冻结后生成并查重，不按成本或实际冲击大小挑选。
- 同一配置/路径方法共同配对；Base-stock不复制训练种子作为独立样本。不把5模型×40路径的200配对当200条独立需求。
- 不修改历史冻结文件；输入、源码、提示、模型、配置和运行时绑定SHA，失败产物保留。
- 新LLM调用与历史开销分列。API新回复具有随机性，历史方法复用与新增变体差异不能全部解释为唯一组件的因果效应。
- 402保存部分结果并按每批登记的次数等待恢复；401/403、程序、审核、哈希或预算错误停止诊断，不覆盖盲重跑。密钥只从Windows User环境读取，不输出/提交。

## 四、阶段1：组件消融的追加分析

### 方法定义

| 名称 | 改动 | 固定内容 | 要回答的问题 |
|---|---|---|---|
| HAPPO | 原纯策略，复用记录 | 原模型/环境 | 主对照 |
| 完整实时反馈F | 原online_feedback，复用记录 | 原全部机制 | 系统参考 |
| 无预测反馈NF | 每个事件仍生成3候选，移除反馈修订请求 | 原信息、最多4事件、搜索筛选、独立复核 | API预测反馈修订的增量 |
| 无独立复核NR | 保留反馈；调用既有select的review=False，按搜索门槛选择 | 原3条搜索路径、原规则和生成时机 | 独立复核的质量/代价权衡 |
| 首次生成FIRST | 只在首次通知生成一次，含原反馈修订，随后每5期重新筛选旧候选 | 原报告、搜索、独立复核 | 多次在线生成的增量 |

NR生成的后3条复核路径不参与打分或提示；应记录实际预测计算减少。NF的请求和FIRST的事件数量也减少。这是组件移除消融，不声称等API或等预测计算预算。没有“去反馈却改提示、候选范围和通知”的组合变体。

### 规模与预算

- [ ] 首先复用共同确认batch01的四类路径、模型11/12做接线开发，只新增NF/NR/FIRST：2×4×3×正常/冲击=48回合、28800节点期。
- [ ] 本小批HTTP首轮上限224，语义请求上限112；若每任务仅一次402恢复，累计上限448/224。这是硬上限，不是预计消费；具体任务划分和恢复次数在批登记中固定。
- [ ] 接线开发只检验行为、错误和成本审计，不按“哪种更好”筛变体。实现修正若涉及决策行为，另登记版本。
- [ ] 通过后，在原共同确认全部10批×4类×五模型上补三变体：新增1200回合、720000节点期；HAPPO与F原400+400回合只读复用，总消融表2000回合、1200000节点期。
- [ ] 完整追加首轮上限5600HTTP/2800语义，含每任务一次402恢复累计11200/5600；已完成且合同相同的小批可复用，相关费用计入累计，不重复运行这些任务。
- [ ] 保存各类型、各模型、各配对改善/持平/退化、真实执行修正率、修复与回退、调用和预测耗时。

**结论范围：** 本阶段为事后追加描述。收益不佳照样报告，不反调F，不对同一旧输入反复试参数至胜出。NR效果若更好，应如实讨论原复核的代价，不能预设所有组件必需。

## 五、阶段2：同信息的非LLM对照开发

**目的：** 检查相同可见信息与预测支持下，一个明确的确定性决策流程能达到什么效果。

### 拟定对照：确定性局部动作搜索D

这不是随机候选，也不称原论文官方策略。使用与F相同的已送达报告、通知、系统状态、HAPPO原动作和合成预测；不读取真实未来、不更新权重、不跨回合记忆。

- 初始动作修正集合为三级节点的常量向量 `{-2,0,2}^3`，共27个含零向量；clip后动作相同的组合确定性去重，全部记录。
- 用同3条搜索预测路径评分，按成本、向量字典序确定性排序，取最多3个非零候选；不足3个以零修正补齐，保持下游selector的候选契约。
- 在反馈阶段，围绕候选0依次考察六个单节点±1邻居（仍执行原动作截断），使用搜索评分，只替换候选0；没有API。
- 后续沿用原3+3筛选与独立复核、接纳门槛、生成时机、5期修正和回合清空。
- 最多27次初始向量评分加6次邻居评分/事件；之后selector计算另列。反馈搜索不读取独立复核结果。
- F的规则可能随状态变化，D的常量向量表达能力较窄；D也有额外候选构建搜索计算。因此本比较不能单独证明语义贡献或等算力优势。需展示两者真实信息字段、搜索次数和墙钟时间。

- [ ] 实现前核对原shadow接口能完整读取因果报告投影、局部状态和动作；列出F/D可见字段逐项对应。
- [ ] 使用相同阶段1小批8个模型×路径配对，无API执行D的16回合、9600节点期；与历史F比较只作开发。
- [ ] 保留动作截断、零动作、重复动作、欠缺候选、预测失败的全部记录，核对不超过注册评分次数。
- [ ] 初始网格固定，不根据正式测试改网格。若接线不支持所需信息或计划修改表达能力，先另写协议，而不是悄悄替换方法。
- [ ] 开发合格标准是信息因果、实现正确与预算可审计，不是必须赢过F。正确但表现强/弱均纳入后续确认。

## 六、阶段3：冻结后的共同新路径机制确认

**目的：** 给论文组件贡献与同信息比较提供前瞻确认。

- [ ] 规模：5模型×4类×10路径×6方法×正常/冲击=2400回合、1440000节点期，其中D为冻结HAPPO上的确定性在线修正，因此参与五模型配对；它不是不依赖模型的Base-stock。
- [ ] 只有F/NF/NR/FIRST在冲击回合调用API。首轮上限8800HTTP/4400语义；含每任务一次402恢复累计17600/8800。D/HAPPO和全部正常回合API0。
- [ ] 正式比较不复用旧路径成本；相同新配置/路径的已完成完整任务才可继续复用，失败恢复单列成本。
- [ ] 主要成本比较为F−NF、F−NR、F−FIRST、F−D四项。20000次交叉重采样，共享五模型轴、每类型独立十路径轴；固定分析随机种子20271652。
- [ ] 四项成本比较统一采用98.75%双侧百分位区间（分位点0.00625/0.99375，Bonferroni家族0.05）；均值与区间上界均<0才写为该项成本优势证据。有限模型种子的bootstrap限制明确披露。
- [ ] F−HAPPO、正常成本、冲击增量差分、分类型和分种子为次要描述，不筛有利指标改主结论。内部接纳指标及全部原始指标仍留档。
- [ ] 独立逐期审核、冻结哈希复核、统计重算、原始记录归档后出结果，不将测试反馈用于调整本版提示。

**成本控制选择：** 若暂不执行该阶段，可先完成阶段1/2，论文将机制贡献写成探索性分析；不把省略正式确认包装成已获得前瞻证据。阶段3不以旧追加成绩“胜出”作为启动门槛，只以方案完整、程序正确、预算登记作为条件。

## 十、时间估算与完成标准

先用阶段1小批的实际吞吐估算完整批次，记录API等待、预测计算和审核时间。此前Base-stock追加约83秒不代表LLM消融也能同样快；API速度、修复和本地预测占比不同。每阶段进入时给出基于实测的时间范围，不预设几小时必完成。

完成标准是全部登记样本、预算和审核齐全，既有及不利结果如实报告，不是一定达到更低成本。本计划不要求再训练五HAPPO，不默认新增MAPPO；新增训练种子、提前期/资源改变与真实数据校准属于后续扩展。
