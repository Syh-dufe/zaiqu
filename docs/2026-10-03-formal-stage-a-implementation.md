# 阶段A实现、流程验证与审阅记录

用户确认正式协议后，本次完成阶段A，额外训练种子及机制实验尚未启动。所有库存状态更新、Actor及候选筛选逻辑复用原有实现；新增接口只接受预生成输入、指定已审计模型、选择评估组和输出目录。

## 实现

- `experiments/formal_evaluation/prepare.py`：预先生成5批、20条正式需求；生成前检索历史种子及路径，生成全部输入后才加载模型评估。
- `experiments/formal_evaluation/run.py`：依次评估完整5批；拒绝覆盖，固定库、来源摘要、依赖及模型参数摘要写入manifest。
- `experiments/formal_evaluation/analyze.py`：复算全部指标、已送达报告历史和20000次配对bootstrap，导出所有输入与逐回合产物。
- `experiments/deepseek_refinement/run.py`：增加固定输入、模型目录和方法选择参数；不指定新增参数时仍保留旧开发模式。

## 流程验证

1. 输入验证的4项检查先确认缺失实现导致失败，再实现并全部通过；覆盖完整201项输入、越界事件和窗口外冲击篡改。
2. 使用旧k=3开发轨迹的前2条，分别跑原HAPPO与LLM库、正常/冲击，共8回合。4,800条逐节点记录与此前完整开发档案逐值相等。
3. 修正固定输入的种子记录先后顺序后，以独立v2名称再验证8回合；逐值相等，输入种子记录正确，调用与训练均为0。v1/v2输出都保留。
4. 读取含中文路径的UTF-8 JSON时，Windows默认编码使独立核验命令报错。证据来自UTF-8显式读取成功；新正式脚本统一显式读取UTF-8，未改模型或输入。旧逐期公开档案为gzip，核验时按压缩格式读取。
5. 正式生成前检索66份历史需求文件、81条独特既有轨迹；本次20条路径均未重复，登记种子未使用。审阅后进一步把仅准备未执行的`batch*.json`纳入未来历史检查。
