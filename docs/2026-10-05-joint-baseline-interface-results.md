# IPPO共同灾情比较接口验证

五个IPPO正常验证best模型已在原环境中重新加载，使用各自7维局部critic配置，没有更新权重。内部作者组件加载标签仍为happo，算法身份明确为ippo。

- 原20正常需求×五模型=100回合，复算成本与训练完工审核逐种子一致，绝对误差阈值1e-8内。
- 复用已暴露v5b batch01四类型的正常/冲击输入，共40回合、24000唯一节点期；不是新测试路径。逐期成本I+B、动作0—20、原需求索引、起始前正常/冲击前缀一致全部通过。
- 记录k3报告观察后的递送，决策前已送达范围必须为floor((period−1)/3)×3；通知延迟标记沿用两期。此批只验证IPPO纯策略部署与报告记录，未运行LLM生成/筛选，不把通知标记检查当作完整LLM控制器审核。
- 五个actor/critic参数哈希前后不变，全部源文件、验证需求、输入和模型档案哈希一致。没有API请求或训练；总140回合耗时约43.07秒。

独立归档审核再次从原24000行复算40回合成本/欠货与模型加载记录，68个原始/源码/协议文件逐字节复制并检查密钥缺席。见[归档清单](artifacts/joint_baseline_interface_v1/export_hashes.json)。captured_stdout.log保存初始Gym提示后的工具捕获输出，初始提示可见运行记录，不声称它是未经截取的完整原始stdout。

本结果只能说明IPPO部署接口一致，不能说明IPPO灾情泛化或实时LLM+HAPPO胜出。下一步按[已写定三方法共同确认协议](superpowers/plans/2026-10-05-joint-baseline-confirmation.md)实现独立运行器和统计审核：五seed×每类10新路径×四类×三方法×正常/冲击，共1200回合720000节点期。此时尚未生成该批新输入，也未启动付费确认。

正式主比较为online_feedback−IPPO的成本和欠货，两个97.5%区间上界与均值均低于零才称较强总体改善证据；HAPPO次要比较另报告。LLM额外报告/通知/状态和预测计算明确披露，不能把系统方案优势直接等同LLM单独贡献。原机制、解析、环境不调整，全部五seed和不利结果保留。
