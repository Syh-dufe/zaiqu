# 方法选择后的独立确认：单次LLM+预测筛选

## 为什么不继续堆迭代

v3固定20条测试中，迭代平均成本下降4.54%、下游积压下降13.66%，但成本差区间[-2.4396,0.0991]跨0；成本退化7条、下游退化10条。单次LLM平均下降3.65%/7.23%，区间[-1.7549,-0.2189]/[-4.7368,-0.0635]均负，成本退化1条、下游退化3条，且请求更少。人工均值更强，保留展示。

用户允许任何改进路线，故选择调用更少且较少退化的单次规则+筛选继续确认。该选择用了20条测试结果，不能把同批20条重新冒充选择后的独立验证，必须另抽新数据；迭代结果也不删除。

## 运行前固定的新实验

- 单次方案算法与v3的llm_single组完全相同：一次请求生成3候选，仅第1条用于该组，若第1条语法无效回退，不换更有利的第2/3条；不请求反馈。20期预测、前5期修正后原策略、每5期重新筛选；阈值、预测、动作上限、现场通知及原HAPPO均保持。
- 实现只加入single-only开关，关闭迭代组和相应请求，不改变原/人工/单次组计算。保留源码哈希；已结束的20条确认采用之前封存的源码哈希，不能称新旧文件字节相同。
- 4批各4条，16条新需求；种子20261044/46/48/50，事件20261045/47/49/51。正常/冲击配对，原HAPPO、人工、单次LLM三组，96回合、57600节点期。
- run-name flash_confirm_single_v3_batch1..4；驱动confirm.py --single-only，合计16次API，系列已用102次，完成后最多118次，不超过120上限。没有为节省预算而重复用旧需求。
- 按需求配对bootstrap20000次，种子20261060，95%百分位区间。主要判据仍成本/下游积压平均差均负，且两项区间上限均负才称较强改善证据；不根据中间结果停止或修改。
- 同时完整呈现人工结果；如人工优于LLM，不将LLM描述为最优。若未通过，如实报告，保留记录，继续分析而不制造成功。
