# 可复用LLM补货算子：设计与开发协议

用户已授权持续改进及调用API，继续brainstorming/writing-plans流程的逐项设计。原HAPPO及环境保持，分支改变的是LLM使用位置，不冒充事件时新生成。

## 为什么新增这一分支

此前每事件生成规则加筛选在新需求上平均改善，但成本区间跨0；频繁反馈增加退化。预测结构诊断以同一16条已看过需求及缓存规则完成：Merton近似预测MAE1.7525 vs残差1.8196，单次LLM成本21.0466 vs21.5630，积压19.1138 vs19.1172；原HAPPO仍21.8228/19.5009。个案仍有成本/缺货退化，不能当作新测试。

两条路线分别是继续每事件请求（调用多、输出随机）与离线发现可复用算子（调用少、在线仅选择）。选择后者作独立新分支，更接近VRPAgent的算子发现/仿真反馈思想，但不是复现其VRP实现。在线仍据新观测筛选/回退，没有HAPPO再训练。此分支不能宣称现场实时LLM推理效果。
