# 冻结HAPPO与DeepSeek反馈修订：预定协议 v1

在付费请求及读取本轮结果前固定。实现采用 writing-plans / executing-plans 的逐项执行流程，延续已获批准的小型设计。

## 实验与停止预算

- 开发需求种子20261011，事件种子20261012，2条原Merton序列，200期；正常和冲击配对。冲击开始索引60..100、持续20..40期，需求1.5倍向上取整截断20。
- 现场通知在事件开始后观察2期才收到，所有组相同；正常回合无通知。本轮假设通知可靠，不能宣称已解决自动检测、虚假通知或真实灾情。
- 四组：原HAPPO、人工规则+预测筛选、单次LLM+预测筛选、迭代LLM+预测筛选。单次组使用初次生成的第一个规则；迭代组使用3个初始规则以及2轮修订。初始请求在同一通知时状态生成后跨组复用，以控制生成随机性。
- 每个事件最多3次请求，本轮最多12次，累计系列最多120次；无自动重试。DeepSeek flash，thinking disabled，温度0.2，max_tokens=3000，timeout=30秒。失败候选回退，不删失败记录。
- 冻结种子11的250000步最佳模型，保留上游提交a7e5a3e83e21565a5799483bc534e39635ec65dd的状态转移和原成本；无训练、无奖励变更。

## 因果预测与筛选

- 当前需求预测以最近5期均值为中心，从最近20期需求减其均值的残差独立重采样，四舍五入截断0..20。仅使用已观察历史，不使用事件结束时间、真实未来需求或事件倍数。
- 每次评分20期（末尾不足则截短），3条公共预测序列用于搜索、另3条用于留出复核。预测种子固定为20261013+1000*trace+period，分批抽样。每5期重新选择。
- 影子状态只复制库存、积压、已知4期在途、已发生动作历史及RNN状态；未来需求由上述预测新建，不复制真实环境eval_data/demand_list。
- 原HAPPO零修正始终参评；候选仅在搜索和留出两批都满足系统成本比零修正低至少1%、下游累计积压不增加时可接受。以搜索成本选择，复核失败回退零修正，不循环选择留出最优。
- 2次修订只接收搜索预测的分数，不接收留出或真实后续结果；每5期的重复评分会使用新的预测批次。本协议的留出是预测样本复核，不能替代独立真实需求测试。
- 所有修正限[-6,6]，订单限0..20。各组可见同一现场状态与需求历史；原模型仍使用原局部观测，额外协调信息和算力的作用通过人工组对照分析。
- 单次与迭代比较同时改变候选数和反馈预算，不能仅归因于反馈。后续需等候选数的消融。
- 实际部署不利用尚未知的原HAPPO反事实结果回退。每5期预测重新检查接受条件；记录已发生预测误差，不因真实测试最终好坏修改本轮算法。
