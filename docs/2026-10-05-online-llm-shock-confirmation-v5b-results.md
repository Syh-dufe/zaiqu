# 原实时LLM跨需求冲击独立确认：v5b

日期：2026-10-05。预注册提交 `ab4b105`；五个HAPPO模型和原实时LLM逻辑保持冻结。未更新HAPPO或DeepSeek权重，未加入随机候选方法。

## 设计与数据隔离

比较纯HAPPO与原 `online_feedback`，交叉训练种子11—15、四类冲击各10条新需求路径，保留正常与冲击配对。共50个子任务、800回合、480,000个唯一节点期、200个模型×冲击路径配对。200个配对来自40条不同基础路径，不能当作200条独立需求样本。

在方法冻结之后生成输入，按登记顺序接受需求种子20271402—20271411；对412条历史路径重新查重，80条基础/冲击路径无精确碰撞，没有按结果择路径。精确查重不能证明需求分布在统计上完全独立。

每批时间偏移依次为−10、−8、−6、−4、−2、0、2、4、6、8。冲击按0起始需求索引定义：

|类型|区间（加时间偏移）|倍率|
|---|---|---|
|单次骤增|[80,100)|1.5|
|持续高需求|[70,120)|1.25|
|两次分离冲击|[75,95)、[115,135)|1.5|
|骤增后回落|[80,100)、[100,140)|1.5、0.5|

增长向上取整并截断20，下降向下取整；实际变化逐路径保存。k=3报告、两期通知延迟、原库存状态转移和订货上限不变。每条路径只有第一次冲击通知；实际类型、未来起止和倍率不提供给LLM。规则只使用已送达报告和当前合法状态。一次反馈修订仍替换候选0，搜索与独立复核路径仍各3条，每5期重新筛选，每回合最多4次生成、16次HTTP，回合间清空记忆。

初次v5登记在校验双峰事件边界时失败，未调用API、未运行仿真、未保存需求输入；内存生成种子20271401被排除。v5b修改双峰起点并重新登记，失败记录和两个版本源码、协议一并归档，没有覆盖失败尝试。

## 主要结果

成本为全200期、3节点共600个节点期的平均 `库存+欠货`，欠货为下游节点0全200期平均欠货。协议中系统成本的实现采用上述平均归一化，而非三节点总和。以下是200个冲击配对的均值：

|方法|平均成本|下游平均欠货|
|---|---:|---:|
|纯HAPPO|22.04636|18.35170|
|原实时LLM反馈＋筛选|21.46470|17.31238|

成本降低 **2.64%**，欠货降低 **5.66%**。以下差值均为LLM减HAPPO，负值表示改善。

|指标|平均差值|预登记95%区间|改善/持平/退化配对数|
|---|---:|---|---|
|成本|−0.58166|[−0.99907, −0.19631]|106 / 33 / 61|
|下游欠货|−1.03933|[−1.94090, −0.34695]|115 / 47 / 38|

预登记交叉bootstrap共20,000次，随机种子20271003；每次共同重采样5个模型，并在每类内分别重采样10条路径，再对四类等权平均。两个共同主指标区间上界均小于零，达到登记的总体改善条件。逐期独立计算与驱动汇总一致。作为事后敏感性，保持四类共同需求种子/时间偏移批次一起重采样：成本区间[−0.91906,−0.25147]、欠货[−1.88991,−0.36448]，方向一致；此分析不替代预登记主分析。

正常环境两方法动作和结果完全一致，正常差值为零，因此本批差分中的差分等于冲击差值。全部五模型的平均成本与欠货差值均为负，但不代表每条路径改善。

## 各类型：次要描述，不能声称全部稳定占优

每类50配对、10条不同路径。分层区间未作多重比较校正，属于次要描述。

|类型|成本差|成本95%区间|欠货差|欠货95%区间|
|---|---:|---|---:|---|
|单次骤增|−0.22417|[−0.71112, +0.27837]|−0.20580|[−0.66720, +0.22260]|
|持续高需求|−0.97063|[−2.10860, +0.08392]|−2.08320|[−4.95202, −0.13379]|
|两次分离冲击|−0.66247|[−1.69952, +0.03561]|−0.87120|[−2.96102, +0.08250]|
|骤增后回落|−0.46937|[−1.56285, +0.34387]|−0.99710|[−2.42151, −0.12400]|

四类平均成本均下降，但四个成本区间均跨零。单次骤增成本有20/50配对退化。结论限于该仿真冲击混合分布下整套在线机制对冻结HAPPO的平均改善；不能声称每类、每次灾情都有效，也不能独立归因于LLM候选内容、反馈或筛选。没有真实灾情校准、道路/车辆仿真或现场验证。

## 调用、失败与审核

- 1724次HTTP、1569次语义请求；未触及首轮3200/1600上限，无额度中断、任务重跑或任务级失败。
- 6,287,995 tokens：提示5,632,749、生成655,246；提示缓存命中3,071,616、未命中2,561,133。没有实际账单金额。
- 189次回复不合法，其中规则数限制60、未知特征110、表达式语法18、JSON格式1。155次为首次回复，34次为修复回复。不能把110个未知特征全部称为大小写错误。
- 800个生成事件、4990个筛选事件；31次初始生成修复后仍失败，使用零修正候选；3次反馈修订修复后仍失败，保留初始候选。没有规则执行异常回退。失败保留在部署机制的总成绩中，不能删去再计算主结果。
- 全800回合/480,000节点期复算成本与欠货；400组正常或通知前动作与状态比较一致。五模型文件及训练元数据、全部冻结源码/协议/输入哈希核验通过。
- 672份原始文件保存；逐期大文件采用无损gzip，解压SHA256与原始字节一致；密钥字节缺席检查通过。原始成本复算、交叉统计及共同批次敏感性由新归档助手计算，未调用实验驱动的汇总函数。
- v3失败与v4开发共374次HTTP、348次语义、1,369,819 tokens。加本确认累计2098次HTTP、1917次语义、7,657,814 tokens，范围只含这一跨冲击系列，不是全项目所有历史实验。

HAPPO种子11、13达到原经验稳定标准；12、14、15由原早停结束，均完整纳入，不能称五种子全部收敛。仅五模型种子的不确定性是统计限制。

## 后续改进依据

当前控制器按通知后的5期时槽生成，通常在前20期内用完四次机会；第二峰或需求回落发生更晚时，仅重新筛选末次候选。这是从源码确认的机制限制，尚未验证是退化的因果原因。下一轮小型开发将比较在相同最大API预算下，依据已送达报告安排生成时机的方案。保持环境、冻结HAPPO、原提示/解析/候选替换与筛选不变，以隔离调用时机变化。当前确认路径一旦用于该改进，即登记为开发资料；升级版确认须重新冻结并生成未见路径。
