# 投稿准备：模型假设与参数来源

记录日期：2026-10-03。基础实现固定为 Liu 作者仓库提交 `a7e5a3e83e21565a5799483bc534e39635ec65dd`；本项目本次整理前版本为 `0215ae0`。本表以实际代码为依据，区分正式论文的说明与作者实现的默认值。

## 1. 研究对象与声明范围

研究对象是突发需求与需求汇总信息滞后下的三级应急物资补给。下游节点解释为社区发放点，中游为区域仓库，上游为供应中心；节点是库存决策主体，不能解释为货车或摩托车。物资是可替代的单类标准批次，时间是离散仿真期，尚未映射为天或小时。

基础参数有可追溯文献和公开实现依据；目前没有实际灾情数据拟合或校准。业务解释不改变库存动力学。新增冲击是机制研究的压力情景，不是特定洪灾的重建。

## 2. 基础模型参数与假设

| 项目 | 实际设定 | 来源定位 | 业务解释与边界 |
|---|---|---|---|
| 网络 | 3节点串行、单一上游 | `external/liu-inventory/envs/serial.py: LEVEL_NUM`；Liu §3.1 | 供应中心—区域仓库—社区点，不含并行仓库或跨区调拨 |
| 补给提前期 | 4期、确定、各节点相同 | `LEAD_TIME`；Liu 表1典型设置 | 每级补给均需等待；没有灾后道路损坏、随机运输延迟 |
| 订货动作 | 整数0..20 | `ACTION_DIM=21`、`action_map` | 每期申请标准物资批次；这是申请量边界，不是车辆运力模型 |
| 初始库存 | 每节点10 | `S_I=10`、`Env.reset` | 统一初始储备，不代表真实库存调查 |
| 初始在途 | 每节点4个在途槽，每槽10 | `S_O=10`、`Env.reset` | 初始已有40批待到货物资，不应遗漏该初始条件 |
| 初始欠货 | 每节点0 | `Env.reset` | 未满足需求逐期结转，可后续补供；无丢单、死亡或逾期失效机制 |
| 每期成本 | 每节点库存与欠货系数均为1 | `H`、`B`、`state_update`；Liu 表1 | 归一化权重，不是实际仓储费用或灾害损失货币估计 |
| 其他成本与损耗 | 固定成本、折扣、随机运输损失均关闭 | `FIXED_COST`、`PRICE_DISCOUNT`、`RANDOM_SHIPPING_LOSS` | 当前结果不覆盖这些业务机制 |
| 上游供给 | 最上游在途新增量等于其动作 | `state_update`；Liu §3.1.1上游无限库存假设 | 外部供应充足，仍受申请量和提前期约束；不代表灾区所有供应无限 |
| 节点交互 | 下游当期订货成为上游当期需求，叠加各自欠货 | `state_update` | 补货可把缺货压力向上游传递；照原代码更新顺序执行 |
| 本地观测 | 库存、欠货、上一期本地需求及4项在途；除以20归一化 | `get_reset_obs`、`get_step_obs` | 7维输入；需求汇总滞后不会抹去本地订单观测 |
| 回合长度 | 实际评估200次状态转移 | `EPISODE_LEN`及本项目评估循环 | 作者生成器生成201个需求值，评估使用索引0..199，保留未消费末值的来源记录 |
| HAPPO奖励 | `0.5*r_i + 0.5*mean(r)` | `ALPHA=0.5`、`get_processed_rewards` | 混合自身与系统平均成本；正式论文公式8的系统总成本表述与代码均值不直接等同，本研究明确采用作者实现 |

不根据成本排序把上述归一化参数改成有利数值。参数不同于实际单位时，正文必须保留“标准批次”“仿真期”“归一化成本”的说明。

## 3. 需求来源

Liu §3.1.3采用 Merton 跳跃扩散思想生成非平稳需求，解释外部冲击下的突增与低谷，并引用 Merton (1976) 和 Glasserman (2004)，六个外生参数指向附录G。正式论文另有 Walmart M5 真实需求实验；本项目当前采用的是模拟需求分支，不沿用其真实销售数据实验结论。

本研究实际调用作者 `envs/generator.py:merton`，默认最大需求20。代码设 `base=10`、初始潜在增量0、`var=15`、`delta=.01`、`delta_t=15`、`u=.5*delta²`、`a=0`、`b=.01`、`lamda=15`，采样 `Z~N(0,1)`、`N~Poisson(15)`、`Z_2~N(0,2²)`。按代码累积、指数变换与整数化；只有未截断序列均值在(0,20)内才接受，随后截断至20。生成器参数名称及尺度按代码报告，不未经核对映射为论文同名符号。

该生成器包含整条路径的接受条件；在线预测使用公开增量的近似传播，不能称为这一接受条件下的精确条件预测，也不能称为实际灾情概率分布。

## 4. 新增灾区与LLM设置

| 项目 | 当前设定 | 依据与性质 |
|---|---|---|
| 需求冲击 | 原需求乘1.5、向上取整、截断20；索引60..100随机开始，持续20..40期 | 本项目预设压力参数；1起算开始期61..101；不是Liu原实验或真实洪灾标定 |
| 灾情通知 | 冲击开始后观察2期，随后决策可收到可靠通知 | 自设信息渠道假设；不提供未来需求、倍数、终止时点，无误报漏报实验 |
| 汇总报告 | 每k期发送非重叠总量/均值，k=1、3、5；下期决策可用 | 借鉴 Kawase 等信息异步更新机制，具体档位自设；不是论文参数复现 |
| 可见状态 | 修正模块可见所有节点当前库存、欠货、在途、历史订单与HAPPO建议；外部需求统计限已送达报告 | 当前中央库存状态可见，需求汇总滞后；不能称全系统通信中断 |
| 重建历史 | 将报告均值重复k次 | 本项目简化；信息滞后与区间平滑共同发生 |
| 预测 | 公开Merton增量近似，6条路径，3搜索+3复核；20期窗口，末尾截短 | 从已收到报告初始化；不读取真实隐藏需求或事件日程；不是完整贝叶斯滤波 |
| LLM算子 | DeepSeek开发阶段生成、等价格式修复后的3条固定规则 | `docs/artifacts/operator_discovery_v1/repaired_library.json`；来源与失败记录保留，在线0 API |
| 动作修正 | 修正截断[-6,6]，四舍五入，订货截断0..20 | 本项目固定动作护栏；不是作者HAPPO训练更新 |
| 筛选 | 成本预测至少改善1%，下游积压预测不增加；3条独立预测复核失败则回退 | 本项目计算条件；不能保证实际实现逐回合改善 |
| 修正期限 | 每次前5期修正，后续影子路径跟随原策略；真实每5期重新评分 | 当前在线选择机制，HAPPO参数冻结 |

预测初始无报告先验10、报告均值加0.5近似潜在需求等实现细节，详见[报告协议](2026-10-03-periodic-demand-reports.md)。固定模型采用seed11官方最佳250000步检查点；训练在295000步达到预定经验平台。训练耐心由作者默认10增至40，须单独声明，见[学习稳定性报告](2026-10-03-empirical-plateau-results.md)。

## 5. 可用于正文的说明

> 本文沿用Liu等公开实现中的三级串行库存系统及其基础参数，将节点解释为供应中心、区域仓库和社区物资发放点。在保持库存更新与基础策略训练规则的条件下，构造短期需求突增和定期需求汇总情景，研究冻结策略的在线修正。数量、时间及成本均采用归一化单位；新增情景参数用于可控仿真及敏感性分析，未由真实灾情数据校准。

欠货衡量可后续补供的未满足物资需求。成本权重1:1用于基准可比性，并不意味着灾区缺货与库存具有相同现实损失。正文不声称模型涵盖紧急医疗不可延期需求、救援公平性、伤亡损失或道路调度。
