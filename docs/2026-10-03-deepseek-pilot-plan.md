# DeepSeek + 冻结 HAPPO：已批准的小实验实施协议

用户已批准正常训练的 HAPPO 不重训，在异常后由 DeepSeek 生成连续执行的补货修正规则。按 brainstorming / writing-plans 工作流落实已批准设计，不增加完整基线排名。

## 固定设定

- 冻结250,000步模型，摘要与现有完成审计一致。原作者环境及 CRunner.eval 不改动，包装向环境传递的动作。
- 接口模型列表已成功读取，显示 deepseek-flash = DeepSeek-V4.1-Flash，以及 deepseek-v4-pro。本轮使用 deepseek-flash，非思考模式、temperature=0.2、max_tokens=1500，JSON输出。API返回标识及用量原样记录；别名不保证底层权重永久固定。
- 新需求种子20261005，原 merton(200,20)，5条，每条200期；事件种子20261006，零起算开始索引均匀整数60..100、持续20..40期、1.5倍向上取整并截断20。每条都有正常/冲击配对，事件表在仿真前生成保存。它不是实际洪灾校准。
- 三组：冻结HAPPO、HAPPO+人工规则、HAPPO+DeepSeek规则。各10个情形，共30个回合；单次生成仅作探索，正式实验需要重复生成。
- 所有组使用同一因果需求检测器：至少25期历史，最近5期均值 > 前20期均值的1.3倍，连续2次满足才触发。只在首次触发后介入；没有触发则不调用API。正常情形也运行检测器。
- 每情形最多一次生成请求，全轮最多10次，超时30秒，无重试或结果筛选。调用期间仿真暂停；记录耗时，不把它冒充真实业务中的零延迟。失败时继续原策略并保留记录。
- LLM接收库存、积压、在途、上期流入需求、近期历史统计和HAPPO基础动作；不接收情形名、事件时间、完整需求序列或未来需求。人工规则可用相同状态信息。中央规则包装可汇集三节点观测，此信息汇集需在论文中披露，不能说与单个分散actor信息完全相同。
- 生成函数用受限JSON条件-表达式表示：最多4条规则，允许有限算术、比较、and/or以及min/max/abs；输入特征来自当前/过去信息，解释只作展示。输出delta，包装限制每节点修正到[-6,6]、四舍五入成整数、最终动作0..20。与人工规则使用相同限制。禁止导入、访问文件/网络和任意Python执行。
- 人工规则预先固定：触发后，若 recent>1.3*baseline 或 backlog>5，delta=ceil(min(6,max(0,(4*max(incoming,recent)+backlog-inventory-pipeline)/4)))，否则0。不按LLM结果调整人工参数。

## 指标及核验

- 每情形平均成本、下游累计/峰值/末期积压、配对变化；报告正常情形的误报和代价。
- 冲击后首次10期额外积压<=5窗口、再次超阈和直到期末持续<=5的窗口，均相对于同组无冲击配对；未观察到完整窗口记右删失。并另外比较同一冲击情形各组的绝对积压。
- 保存逐期基础与实际动作、触发时刻、输入提示词、API原始响应、规则、耗时/token、所有失败；不保存密钥或请求头。
- 参数前后摘要相同；无介入组与各组触发前动作一致；每回合200期，三组触发期应一致（检测器只用外生历史需求）。不执行训练更新。
