# 必做实验执行计划

> **For agentic workers:** 使用executing-plans按本清单执行，不修改历史冻结文件。

**Goal:** 完成用户批准的组件、信息、冲击强度/时点与开销实验。

**Architecture:** experiments/submission_required独立适配原运行器，保留原Client/SYSTEM与完整策略，单驱动依次执行开发、确认、敏感性。旧结果只用于来源与开销核对。

**Tech Stack:** 项目Python/PyTorch CPU、原DeepSeek API、JSON/CSV与交叉重采样。

- [ ] common.py：显式路径加载、来源合同、脱敏、精确文件哈希、密钥环境读取。
- [ ] controller.py：只适配NF/NR/FIRST/D；F分派原控制器。记录D构建预算与同信息字段。
- [ ] run_online.py：复制原部署接线，动态方法组和敏感性输入验证，检查原提示/模型/正常与通知前动作。
- [ ] audit.py/analyze.py：全节点期/报告/请求与组件合同核验，成本四比较固定校正区间，全部负例。
- [ ] reliability.py：复用旧50任务及所有失败尝试，核对历史1713HTTP，按原始请求统计开销，不虚构账单。
- [ ] preflight.py：在旧已暴露batch01进行无API真实环境接线，不计为性能结果；先核对零候选、全部分派与异常保护。
- [ ] batch.py：注册固定预算与源码模型合同，生成查重新输入，永久启动锁、串行运行/单次402恢复，原始记录与逐任务审核。
- [ ] register：独立冻结所有新源码、旧依赖、模型、输入、协议；先提交后首次生成新输入；预检通过后运行。
- [ ] run：80回合开发（包含16回合纯HAPPO接线核验）→2400回合新机制确认→2000回合强度时点；不按效果跳过或更改方案。
- [ ] archive：逐文件脱敏检查、CSV无损gzip、清单SHA、报告README更新，提交推送。

源码验证与任务审核属于实验执行要求。小批只检验正确性，不据成绩改变主方法。重启需独立故障诊断，不能删除启动锁或覆盖失败目录。
